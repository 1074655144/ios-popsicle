## 固件里读不到、必须上真机采集

- `fb_w`（pending_live）：measured by shim/hello + SSPP registers, NOT the panel's physical width
- `fb_h`（pending_live）：byron's public spec is also 1200x2608, but the framebuffer must be measured
- `fb_stride`（pending_live）：read SSPP source stride register; do NOT assume width*4
- `fb_format`（pending_live）：SSPP format register at +0x30
- `touch_irq_gpio`（pending_live）：TLMM GPIO; distinguish main vs rear by /proc/interrupts counter while touching
- `tlmm_base_real`（pending_live）：CRITICAL: the real base is 0x0f100000, NOT the DT value. Reading 0x0f065000 hangs the SoC (upstream t2 test). GPIO n = 0x100000 + 0x1000*n
- `thermal_table`（pending_live）：byron 8000mAh + different chassis: all thresholds and the 95C junction hysteresis must be redone
- `battery_gauge`（pending_live）：byron 8000mAh + P3/G2 charging ICs
- `charger_ic`（pending_live）：read /sys/class/power_supply + vendor DTBO
- `brightness_dcs`（pending_live）：DSI test-pattern FIFO kickoff; byron's M10 panel uses a different range
- `page_size_16k`（pending_live）：XNU wants 16K pages; must be probed in a tiny bootloader before committing to a port
- `abl_load_addr`（pending_live）：where ABL places the payload; upstream step 1 probe
- `userdata_dev`（pending_live）：always resolve /dev/block/by-name/userdata, never hardcode sdX
- `userdata_lba`（pending_live）：dm-default-key table: full-block mapping, offset 0
- `pinned_extents`（pending_build）：generated by phone_prepare.sh on the byron unit; FIEMAP positions are device-specific
- `firmware_files`（pending_firmware）：extract from /vendor/firmware_mnt (vendor 分区尚未解包); byron 是 WCN786x; never commit vendor blobs
- `stock_boot_b_sha256`（pending_build）：tools/backup.sh on the byron unit, before any bootmgr experiment

> `soc_shared` 且判定为 `same` 的字段才可直接沿用；`board_specific` 即使数值相同也必须核对来源（例如同为 1200x2608 并不代表 framebuffer 一致）。
